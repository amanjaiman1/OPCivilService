# PWA transition

Keep existing web, install prompts, service worker and web push while native
parity and reliability are being verified. Introduce internal distribution, then
offer a controlled beta to people with fully synced accounts. Have beta users
check the most recent Journal and Life records before trying native edits.
Offline or browser-only data must first be synced or recovered from the
original browser, including unsent attachments and held saves.

After independent Android and iOS approval, offer native as another way to
access the same account. Expand gradually while monitoring recovery, schema
mismatch, auth link failures and token revocation. Reduce PWA installation
promotion only after supported native flows have parity and the existing
PWA continues to serve those who depend on it. Stop native push or distribution
independently if a rollout needs reversal. Preserve snapshots and old-client
version protections during recovery.
